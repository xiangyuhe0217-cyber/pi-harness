# W5：Prompt A/B + 3x 复现 + Context Stress

## 1. Prompt A/B（Phase 2 live）

在 6 条正常任务上做 A/B：

- **A**：原始 prompt。
- **B**：追加 “先跑测试、失败就修；只用 fs_* / shell_exec；不要用管道/&&/; /重定向”。

| 版本 | pass | tokens | cost | audit blocks | verdict |
|---|---|---|---|---|---|
| A | 6/6 | 50,942 | $0.004360 | 2 | ok=6 |
| B | 6/6 | 69,900 | $0.005907 | 1 | ok=3, wasteful=3 |

结论：**B 没有提升 pass，但 tokens +37%、cost +35%，且触发更多重复动作 → 拒绝。**
这是一个很有价值的负结果：prompt 改动必须 live A/B，不能靠回放；没有收益就回滚。

## 2. p2 三次复现

| 轮次 | pass | tokens | audit blocks |
|---|---|---|---|
| p2 run1 | 6/6 | 62,315 | 3 |
| p2 run2 | 6/6 | 61,953 | 2 |
| p2 run3 | 6/6 | 62,173 | 1 |

结论：pass 稳定 6/6；blocked 数有噪声（1–3），所以策略改动不能只看一次 live run，要结合 replay。

## 3. Context stress（C001）

任务：读一个 154KB 的 `large.txt`，写三行摘要。

| 指标 | 值 |
|---|---|
| status | pass |
| steps / tools | 10 / 22 |
| tokens | 35,490 |
| max_input_tokens（含 cacheRead） | 5,620 |
| utilization | 0.043 |
| compaction_count | 0 |
| repeated `fs_read large.txt` | 3 次 |
| decay_ratio | 2.4 |
| verdict | wasteful |

结论：

- 上下文指标已经能算（`max_input` 要含 cacheRead，否则严重低估）。
- **compaction 没有触发**：窗口 131k，阈值约 114k；单任务读文件会被 pi 截断（50KB），很难到阈值。
- 要真正触发 context anxiety，需要：更小的 context window 模型、或多轮长会话、或更大的工具输出（不截断）。
- 重复读同一文件 3 次、decay 2.4，说明 C001 是一个很好的“效率调优”样本。

## 4. 本轮学到的三件事

1. **Prompt 改动要用 live A/B**：B 没收益还涨成本，直接回滚。
2. **策略改动要用 replay + 多次 live**：p2 的 pass 稳定，但 blocked 数噪声大。
3. **Context 指标要含 cacheRead**：只算 `input` 会低估真实上下文。
